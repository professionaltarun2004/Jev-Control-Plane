# Failure Lab

The authoritative research methods are in [EXPERIMENT_PROTOCOL.md](../EXPERIMENT_PROTOCOL.md). This guide covers repository use and the limits of the current implementation.

## Run a mock plumbing experiment

From the repository root:

```powershell
python -m pip install -e .
python examples/run_mock_experiment.py
```

Each run gets a new directory under `experiments/runs/` with a manifest, decision-level `results.jsonl`, and summary. Failed cases remain in the output. Mock latency and throughput describe the local harness only.

## Data layout

Each split keeps `cases.jsonl` and optional `annotations.jsonl` sidecars. Cases contain state, decision, and ground truth with provenance/certainty; annotations contain perturbation family, description, and optional matched `base_case_id`. See [dataset details](datasets/README.md) and the [ground-truth construction rules](datasets/ground_truth_rules.md).

## Experimental discipline

Development supports iteration. Validation supports protocol and policy selection. A LOCK freezes the Validation configuration, Validation run artifact digest, data/annotation digests, software/code identity, and prepared Holdout digests. A lock permits one Holdout attempt for that exact data snapshot; interrupted attempts remain claimed. This is an accidental-drift gate, not tamper-proof storage or a statistical guarantee. See the protocol for definitions and limitations.

Metrics distinguish evidence observations (agreement, disagreement, unmapped views, confidence/probabilities) from outcome categories (final-action, Jev-consensus, policy, or runner errors). A disagreement is not itself an outcome error. Accuracy is exact final-action agreement among completed decisions; runner errors are counted separately. Calibration, ECE, Brier score, risk-coverage, SAC, trajectory outcomes, and cost are not reported without a supporting design and data.

No charts are generated from the current small synthetic fixture. A visualization should be added only when machine-readable experiment results support an interpretable plot.

### Historical mock observations

The three preserved pre-M2.5 mock runs each contain 8 attempted/completed Development decisions, 5 exact-action matches, 3 mismatches, 8 policy escalations, and 0 runner errors. Thus the recorded mock accuracy is 62.5% and escalation rate is 100% in each run. Median local mock loop times were 0.207 ms, 0.221 ms, and 0.475 ms respectively; these are harness observations and not Jev latency or a meaningful throughput comparison. Each run has fewer than 20 observations, so its p95 was withheld. The summary labels and case-family analysis in these historical artifacts follow the old taxonomy, including disagreement-as-failure; the corrected M2.5 runner separates evidence from outcomes. These numbers characterize only the old deterministic fixture and must not be described as Jev findings.

The latest current-schema mock smoke run attempted 8 Development decisions: 5 matched ground truth, 3 did not, all 8 escalated, 0 runner errors; accuracy was 62.5%, escalation rate 100%, and evidence status was 1 agreement / 7 disagreements. Median local mock-loop time was 0.357 ms and p95 was withheld at n=8. Its matched irrelevant-context pair retained identical expected action; both outputs escalated and both missed the expected ALLOW. These deterministic mock runs validate artifact generation and analysis wiring only; they are not Jev observations or evidence of an irrelevant-context effect.
